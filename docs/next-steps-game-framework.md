# Next Steps: Game Framework Consumer Track

This track assumes the packed-cell/material/shader backend is being built
elsewhere. Do not duplicate that work here. The goal is to make the current
grey-border + green-player prototype a solid consumer of that backend once it
arrives.

## Current State

- The project now has a modular scene structure:
  - `GameRoot`
  - `SimBackend`
  - `SimDisplay`
  - `Player`
  - `CameraRig`
  - `DebugOverlay`
  - `InputRouter`
  - `SaveManager`
  - `GameState`
- The player can move as a simple green rectangle.
- The visible world is still mostly a simple bounded compute-sim test area.
- `SimBackend` exposes useful API boundaries, but its CPU grid mirror is not a
  final source of truth. It is updated by brush writes, not by simulated falling
  material movement.

## Recommendation

Improve the character/framework and interaction layer next. Do not start real
world generation yet.

World generation should eventually leverage the material registry, packed-cell
format, solidity rules, temperature/reaction data, and chunk/save layout. Since
those are still pending, building generation now would either be throwaway or
would accidentally define backend constraints from the wrong layer.

## Immediate Priority

### 1. Stabilize Player Movement

Goal: make the green rectangle feel like a controllable prototype character
before adding art or combat.

Tasks:

- Add coyote time for jumps.
- Add jump buffering.
- Add acceleration/deceleration instead of instantly setting horizontal speed.
- Add max fall speed.
- Add variable jump height when jump is released early.
- Add simple facing direction based on movement/aim.
- Add exported tuning values grouped clearly in `player.gd`.
- Add debug display fields for:
  - velocity
  - grounded state
  - current cell position
  - current aim cell

Exit check:

- Player can run, stop, jump, and land predictably on the current stone border.
- Movement still works at different camera zoom levels.

Good cheaper-agent work:

- Add exported tuning variables.
- Add debug overlay fields.
- Add simple placeholder visual changes for facing direction.

Needs stronger-agent review:

- Collision edge cases.
- Ground detection.
- Any changes that touch `SimBackend.is_solid_region()`.

### 2. Fix the Collision Contract

Goal: make it explicit what the player is colliding with.

Current issue:

- `SimBackend.cpu_grid` is a partial mirror.
- Brush edits update it.
- GPU simulation movement does not currently synchronize back into it.
- Therefore player collision is currently trustworthy for static stone borders
  and direct brush edits, but not for dynamic settled materials.

Tasks:

- Rename/comment the current CPU grid as a temporary collision mask, not the
  final sim state.
- Add a documented backend method:
  - `get_collision_mask_region(cell_rect: Rect2i) -> PackedByteArray`
- Add a documented backend method:
  - `sync_collision_region(cell_rect: Rect2i) -> void`
- Decide with the backend agent whether collision will use:
  - a CPU-side solidity mirror,
  - a coarse solidity grid,
  - small GPU readbacks around entities,
  - or a hybrid.
- Keep player collision querying only through `SimBackend`; do not let `Player`
  know about textures, RIDs, packed formats, or material IDs beyond tool use.

Exit check:

- The code clearly says whether collision is using temporary static data or
  real backend-synchronized solidity.

Good cheaper-agent work:

- Add comments and debug labels.
- Add placeholder methods that return current behavior.

Needs stronger-agent review:

- Final readback/mirror strategy.
- Performance implications of per-frame collision queries.

### 3. Improve Interaction Without Depending on New Materials

Goal: make digging/placing feel like real character interaction while still
using the current simple material IDs.

Tasks:

- Add a cursor/brush preview in world space.
- Clamp interaction to player range.
- Show blocked/allowed state in the preview.
- Add brush radius adjustment input.
- Add tool mode state:
  - dig
  - place sand
  - place water
  - debug stone
- Make debug stone placement require debug mode.
- Prevent normal tools from editing immutable border/foundation cells.
- Ensure `interact_secondary` always maps to dig/erase.

Exit check:

- Player can aim, see the affected area, dig/place only within range, and never
  accidentally erase the outer border.

Good cheaper-agent work:

- Cursor preview scene.
- Radius UI.
- Tool label polish.

Needs stronger-agent review:

- Brush-to-cell conversion.
- Border/foundation protection.
- Interaction command flow.

### 4. Add a Small Test Chamber

Goal: create a better playground without committing to world generation.

This should be hand-authored or generated by a tiny temporary initializer, not
the real procedural generation system.

Tasks:

- Replace the empty interior with a simple test layout:
  - floor
  - one low platform
  - one vertical wall
  - one small sand pocket
  - one water pocket
  - clear spawn point
- Keep it in a `TestChamber`/debug setup path.
- Do not build biomes, caves, rooms, seeds, chunk streaming, or hub/dungeon
  transitions yet.

Exit check:

- The player can move, jump, dig, and place in a small space that exercises
  collision and interaction.

Good cheaper-agent work:

- Add hardcoded temporary layout data.
- Move spawn point to a sensible location.
- Update README controls.

Needs stronger-agent review:

- Where test initialization belongs so it can be deleted later cleanly.

### 5. Save/Load Contract Only

Goal: avoid painting into a corner before the packed format exists.

Tasks:

- Keep `SaveManager` as a schema boundary.
- Add versioned top-level save data:
  - `save_version`
  - `area_id`
  - `player_position`
  - `current_tool`
  - `sim_payload`
- Make `sim_payload` an opaque dictionary returned by `SimBackend`.
- Do not implement real compressed cell saves until packed cells/chunks land.

Exit check:

- Save/load can round-trip player position and tool state.
- Sim data is clearly stubbed or opaque.

Good cheaper-agent work:

- JSON file path handling.
- Save/load key binding or debug buttons.
- README notes.

Needs stronger-agent review:

- Versioning and restore order.

## Work to Defer

Do not start these until the backend work lands:

- Real procedural cave/world generation.
- Material-driven biome generation.
- Fire, gas, temperature, reactions.
- Rigid body extraction.
- NPC hazard grids.
- Quest predicates over simulated material volumes.
- Full cell/chunk serialization.
- Any UI that depends on inventory, dialogue, NPCs, or quests.

## Backend Integration Questions

Ask/answer these before consuming the packed-cell backend:

- What is the canonical material ID registry?
- Which material property marks solidity?
- Is solidity computed from material ID only, or from packed state too?
- How does gameplay request cell edits?
- Are brush edits applied on CPU, GPU, or both?
- How does the game query a small region around the player every physics frame?
- Is there a cheap active/dirty region signal for debug overlays?
- What data does `SimBackend.capture_save_state()` return?
- What order should restore use: sim first, then entities, or staged restore?
